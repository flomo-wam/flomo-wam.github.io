3D Scene Flow as a World Action Model Intermediate for Learning from Human Video

Same text as the image version. Posts 1, 2, 3, and 5 carry videos; posts 4 and 6 keep the result figures. Collaborator handles and arXiv link remain to fill in post 7.

  1. 01

    1 / 8

    [1/8] Most world action models learn to act by predicting videos. We find that predicting how the scene moves in 3D performs better. Introducing FloMo: a world action model that uses 3D motion as the link between video pretraining and robot control.
  2. 02

    2 / 8

    [2/8] Videos contain extraneous features like texture and lighting. The action that produces the next state depends only on how the scene moves. So FloMo predicts 3D scene flow, the motion of all points in the scene, and renders it as an RGB video.
  3. 03

    3 / 8

    [3/8] Here's how FloMo works. Because scene flow is rendered as RGB, the frozen VAE from Wan 2.2 encodes it into the same latent space as video, so no new tokenizer is needed. Given an image and an instruction, the pretrained 5B backbone jointly predicts scene flow and robot actions.
  4. 04

    4 / 8

    [4/8] On a bimanual YAM robot, FloMo outperforms SOTA baselines that predict video (DreamZero) or 2D point tracks (AMPLIFY) on tasks it never saw in robot data. In RoboTwin simulation, it also outperforms SOTA WAM and VLA baselines.
  5. 05

    5 / 8

    [5/8] Why does motion work better than video? Future motion is easier to predict but still contains action info. These two analyses point to the same conclusion: motion is a more direct bridge from observation to action than pixels.
  6. 06

    6 / 8

    [6/8] A human hand and a robot gripper look nothing alike, but they can move an object in the same manner. The object's scene flow is the same in both cases, so FloMo can learn from human videos that have no robot action labels.
  7. 07

    7 / 8

    [7/8] Removing only the human video drops average OOD success from 60% to 7%. The robot data contains none of the tasks, while the human video covers all three motion classes. The generalization comes from human video, made transferable by our representation of 3D motion.
